# Frontend Architecture — Pleco

You are an expert frontend developer specializing in React 19, TypeScript, TanStack Router, and modern UI/UX. Follow these architectural patterns for the Pleco frontend application.

## Framework Stack

- **Build Tool**: Vite 7
- **React**: React 19
- **TypeScript**: 5.9.3+ (strict mode)
- **Routing**: @tanstack/react-router (file-based, auto code-splitting)
- **Data Fetching**: @tanstack/react-query
- **Client State**: @reduxjs/toolkit + react-redux
- **HTTP Client**: axios
- **Forms**: react-hook-form + @hookform/resolvers
- **Validation**: Zod 4
- **Styling**: Tailwind CSS v4 (@tailwindcss/vite) + tw-animate-css

- **Package Manager**: pnpm
- **Dev Tools**: @tanstack/devtools-vite, react-query-devtools, router-devtools

## Routing — TanStack Router

Routes are file-based and auto-generated by `@tanstack/router-plugin/vite`. The route tree is output to `src/routeTree.gen.ts` — never edit this file manually.

### Adding a New Route

Create a file in `src/routes/`. The file path determines the URL:

```
src/routes/index.tsx        → /
src/routes/about.tsx        → /about
src/routes/projects/        → /projects (layout)
src/routes/projects/index.tsx → /projects
src/routes/projects/$id.tsx → /projects/:id
```

### Route Component Pattern

```typescript
import { createFileRoute } from '@tanstack/react-router'

export const Route = createFileRoute('/projects/')({
  component: ProjectsPage,
})

function ProjectsPage() {
  return <div>Projects</div>
}
```

### Route with Data Loading

```typescript
import { createFileRoute } from '@tanstack/react-router'
import { projectQueryOptions } from '@/queries/projects.query-options'

export const Route = createFileRoute('/projects/$id')({
  loader: ({ context: { queryClient }, params: { id } }) =>
    queryClient.ensureQueryData(projectQueryOptions.byId(id)),
  component: ProjectDetailPage,
})

function ProjectDetailPage() {
  const { id } = Route.useParams()
  const data = Route.useLoaderData()
  return <div>{data.name}</div>
}
```

### Route with Search Params

```typescript
import { createFileRoute } from '@tanstack/react-router'

const searchSchema = z.object({

export const Route = createFileRoute('/projects/')({

  // ...
```


## State Management

### Server State — TanStack React Query

Use React Query for all server/async state. The query client is configured in `src/queries/index.ts`.

**Query Options Pattern:**

```typescript
// src/queries/projects.query-options.ts
import { queryOptions } from '@tanstack/react-query'
import { projectsService } from '@/api/projects.service'

export const projectQueryOptions = {
  all: () =>
    queryOptions({
      queryKey: ['projects'],
      queryFn: () => projectsService.getAll(),
    }),

  byId: (id: string) =>
    queryOptions({
      queryKey: ['projects', id],
      queryFn: () => projectsService.getById(id),
      enabled: !!id,
    }),
}
```

**Using Queries in Components:**

```typescript
import { useQuery } from '@tanstack/react-query'
import { projectQueryOptions } from '@/queries/projects.query-options'

const ProjectList: React.FC = () => {
  const { data, isLoading, error } = useQuery(projectQueryOptions.all())

  if (isLoading) return <Loader />
  if (error) return <ErrorMessage error={error} />

  return (
    <ul>
      {data?.map((project) => (
        <li key={project.id}>{project.name}</li>
      ))}
    </ul>
  )
}
```

**Mutations:**

```typescript
import { useMutation, useQueryClient } from '@tanstack/react-query'
import { projectsService } from '@/api/projects.service'

const useCreateProject = () => {
  const queryClient = useQueryClient()

  return useMutation({
    mutationFn: projectsService.create,
    onSuccess: () => {
      queryClient.invalidateQueries({ queryKey: ['projects'] })
    },
  })
}
```

### Client State — Redux Toolkit

Use Redux for global UI state (theme, sidebar, auth tokens, etc.). Keep it minimal — prefer React Query for server state and local `useState` for component state.

**Slice Pattern:**

```typescript
// src/stores/slices/appSlice.ts
import { createSlice, type PayloadAction } from '@reduxjs/toolkit'

interface AppState {
  theme: 'light' | 'dark'
  sidebarOpen: boolean
}

const initialState: AppState = {
  theme: 'light',
  sidebarOpen: false,
}

const appSlice = createSlice({
  name: 'app',
  initialState,
  reducers: {
    setTheme: (state, action: PayloadAction<'light' | 'dark'>) => {
      state.theme = action.payload
    },
    toggleSidebar: (state) => {
      state.sidebarOpen = !state.sidebarOpen
    },
  },
})

export const { setTheme, toggleSidebar } = appSlice.actions
export default appSlice.reducer
```

**Usage with Typed Hooks:**

```typescript
import { useAppDispatch, useAppSelector } from '@/stores'

const Component: React.FC = () => {
  const theme = useAppSelector((state) => state.app.theme)
  const dispatch = useAppDispatch()

  const handleToggle = () => {
    dispatch(setTheme(theme === 'light' ? 'dark' : 'light'))
  }
}
```

## HTTP Client — Axios

The axios instance lives in `src/api/index.ts` with request/response interceptors for auth tokens and error handling.

**Service Layer Pattern:**

```typescript
// src/api/projects.service.ts
import apiClient from '@/api'

export interface Project {
  id: string
  name: string
  description: string
}

export const projectsService = {
  getAll: () => apiClient.get<Project[]>('/projects'),
  getById: (id: string) => apiClient.get<Project>(`/projects/${id}`),
  create: (data: Omit<Project, 'id'>) => apiClient.post<Project>('/projects', data),
  update: (id: string, data: Partial<Project>) => apiClient.patch<Project>(`/projects/${id}`, data),
  delete: (id: string) => apiClient.delete(`/projects/${id}`),
}
```

Note: The response interceptor strips the axios wrapper — `apiClient.get()` returns `response.data` directly.

## Forms — react-hook-form + Zod

```typescript
import { zodResolver } from '@hookform/resolvers/zod'
import { useForm } from 'react-hook-form'
import { z } from 'zod'

const projectSchema = z.object({
  name: z.string().min(1, 'Name is required'),
  description: z.string().optional(),
})

type ProjectFormValues = z.infer<typeof projectSchema>

const ProjectForm: React.FC = () => {
  const { register, handleSubmit, formState: { errors } } = useForm<ProjectFormValues>({
    resolver: zodResolver(projectSchema),
    defaultValues: { name: '', description: '' },
  })

  const handleFormSubmit = (data: ProjectFormValues) => {
    // submit logic
  }

  return (
    <form onSubmit={handleSubmit(handleFormSubmit)}>
      <input {...register('name')} />
      {errors.name && <span className="text-destructive text-sm">{errors.name.message}</span>}
      <button type="submit">Create</button>
    </form>
  )
}
```

## Styling — Tailwind CSS v4

### Theme

All theme variables are defined in `src/styles.css` using CSS custom properties (oklch colors) with light/dark mode support. The `@theme inline` block maps CSS variables to Tailwind utilities.

```typescript
// ✅ Good — use theme variables
<div className="bg-background text-foreground">
  <button className="bg-primary text-primary-foreground hover:bg-primary/90">
    Click me
  </button>
</div>

// ❌ Bad — don't hardcode colors
<div className="bg-white text-black">
  <button className="bg-blue-500 text-white">Click me</button>
</div>
```

### cn() Utility

Use `cn()` from `@/lib/utils` for conditional class merging:

```typescript
import { cn } from '@/lib/utils'

<button className={cn('px-4 py-2 rounded', isActive && 'bg-primary text-primary-foreground')} />
```

## UI Components — Shadcn Pattern

Base UI components go in `src/components/ui/`. Follow the cva + Radix UI pattern:

```typescript
// src/components/ui/button.tsx
import { Slot } from '@radix-ui/react-slot'
import { cva, type VariantProps } from 'class-variance-authority'
import { cn } from '@/lib/utils'

const buttonVariants = cva(
  'inline-flex items-center justify-center rounded-md text-sm font-medium transition-colors',
  {
    variants: {
      variant: {
        default: 'bg-primary text-primary-foreground hover:bg-primary/90',
        destructive: 'bg-destructive text-destructive-foreground hover:bg-destructive/90',
        outline: 'border border-input bg-background hover:bg-accent hover:text-accent-foreground',
        secondary: 'bg-secondary text-secondary-foreground hover:bg-secondary/80',
        ghost: 'hover:bg-accent hover:text-accent-foreground',
        link: 'text-primary underline-offset-4 hover:underline',
      },
      size: {
        default: 'h-10 px-4 py-2',
        sm: 'h-9 rounded-md px-3',
        lg: 'h-11 rounded-md px-8',
        icon: 'h-10 w-10',
      },
    },
    defaultVariants: {
      variant: 'default',
      size: 'default',
    },
  },
)

interface ButtonProps
  extends React.ButtonHTMLAttributes<HTMLButtonElement>,
    VariantProps<typeof buttonVariants> {
  asChild?: boolean
}

const Button: React.FC<ButtonProps> = ({ className, variant, size, asChild, ...props }) => {
  const Comp = asChild ? Slot : 'button'
  return <Comp className={cn(buttonVariants({ variant, size, className }))} {...props} />
}

export { Button, buttonVariants }
```

## Code Style (Biome)

Biome handles both linting and formatting. Key conventions:

- **Single quotes** for strings
- **No semicolons**
- **2-space indentation**
- **100-character line width**
- Imports are auto-organized

Run `pnpm lint` to check, `pnpm lint:fix` to auto-fix.

## Path Aliases

```typescript
// ✅ Good — use the @/ alias
import { Button } from '@/components/ui/button'

import { useAppSelector } from '@/stores'

// ❌ Bad — don't use relative paths across directories
```

The `@/` alias maps to `src/` (configured in `tsconfig.json`).

## State Management Decision Tree

1. **Local UI state** (toggle, input value) → `useState`
2. **Server/async data** (API responses, cached data) → React Query
3. **Global UI state** (theme, sidebar, auth) → Redux Toolkit
4. **URL state** (search params, filters) → TanStack Router search params
5. **Form state** → react-hook-form

## File Naming

- Components: `PascalCase.tsx` (e.g., `ProjectCard.tsx`)
- Non-component files: `kebab-case.ts` (e.g., `projects.service.ts`)
- Route files: follow TanStack Router conventions (`index.tsx`, `$id.tsx`, `__root.tsx`)
- Test files: `*.spec.ts` or `*.test.ts`
